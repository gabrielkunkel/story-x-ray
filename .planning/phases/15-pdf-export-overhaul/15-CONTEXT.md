# Phase 15: PDF Export Overhaul - Context

**Gathered:** 2026-04-05
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the current `window.print()` PDF with a real downloadable multi-page PDF file generated by jsPDF + autoTable. The PDF has two modes: "Without Scores" (portrait, 5 base columns) and "With Scores" (landscape, 17 columns). A small modal on the existing PDF button lets the user choose before generating. Phase 16 will wrap this in an export dropdown — Phase 15 only needs to make the PDF work and expose the modal from the current button.

</domain>

<decisions>
## Implementation Decisions

### PDF orientation by mode
- **D-01:** "Without Scores" exports in portrait orientation — 5 columns: Step, Label, Act, Beat Text, Notes
- **D-02:** "With Scores" exports in landscape orientation — 17 columns: Step, Label, Act, Beat Text, Notes, then per dimension (Connection, Pressure, Hope, Stability): Actual, Target, Delta

### Score column layout
- **D-03:** Score columns grouped per dimension: Conn A | Conn T | Conn Δ | Pres A | Pres T | Pres Δ | Hope A | Hope T | Hope Δ | Stab A | Stab T | Stab Δ
- **D-04:** Delta displayed as +N / −N / — (matching existing PrintLayout pattern)

### Empty/unset scores
- **D-05:** Actual scores stored as 0 display as `—` (em dash) in the PDF, not `0`
- **D-06:** Target scores always show their numeric value (they are always set from static config)

### "With/Without Scores" choice UI
- **D-07:** Clicking the existing "↓ PDF" button opens a small React modal with two choices: "Without Scores" and "With Scores"
- **D-08:** The modal should be a standalone component (e.g., `PdfExportModal`) so Phase 16's export dropdown can import and reuse it directly
- **D-09:** Modal closes after generating the PDF (no success message needed)

### PDF header
- **D-10:** PDF opens with a header row (full-width, not a table row): Story title on one line, then author · genre · export date on a second line, with a horizontal rule separating header from table
- **D-11:** If author or genre are empty strings, omit them from the meta line (match PrintLayout logic)

### Table behavior
- **D-12:** All 16 steps appear as rows — empty beatText and notes cells are left blank (not `—` or placeholder text)
- **D-13:** Column headers repeat on each page (jsPDF-AutoTable default behavior via `showHead: 'everyPage'`)
- **D-14:** Step column shows zero-padded number: `01`, `02`, ... `16`
- **D-15:** Act column shows full label: `Act I`, `Act IIA`, `Act IIB`, `Act III`

### Library
- **D-16:** Use `jspdf` + `@types/jspdf` and `jspdf-autotable` — install as production dependencies
- **D-17:** PDF generation logic lives in `src/utils/export.ts` as a new `exportStoryAsPDF(story: Story, includeScores: boolean): void` function

### Integration with existing code
- **D-18:** `handleExportPDF` in `StoryWorkspacePage.tsx` becomes `handleOpenPdfModal` — opens the modal instead of calling `window.print()`
- **D-19:** `PrintLayout` component and its CSS can be removed once the new PDF export is wired in (it was the old print-only approach)

### Claude's Discretion
- Column widths within the autoTable (within the orientation constraints above)
- Font size and cell padding
- Whether to use `doc.save()` or Blob download — whatever is simpler with jsPDF

</decisions>

<specifics>
## Specific Ideas

- Portrait for basic export, landscape for scores — jsPDF supports setting orientation at document creation: `new jsPDF({ orientation: 'landscape' })`
- The modal is the same "Export PDF" pattern that Phase 16 will call from the dropdown, so keep it composable
- `jspdf-autotable` is the standard plugin; it adds `doc.autoTable()` to the jsPDF instance

</specifics>

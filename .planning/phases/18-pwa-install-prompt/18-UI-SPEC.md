## Component Specification: PWAInstallCallout

### Structure

The callout is a **non-modal inline banner**, not an overlay. It renders inside `StoryWorkspacePage` below `BoardHeader` and above the board body. It does not use `capture-overlay` or any backdrop.

```
┌─────────────────────────────────────────────────────┐
│  [Install icon]  Headline text             [× Dismiss]│
│                  Body text (benefit statement)        │
└─────────────────────────────────────────────────────┘
```

### CSS Class Inventory (new classes to create)

| Class | Purpose |
|-------|---------|
| `.install-callout` | Root container — inline banner, no position:fixed |
| `.install-callout__icon` | Left icon area (optional, can be omitted for simplicity) |
| `.install-callout__content` | Flex column: headline + body text |
| `.install-callout__headline` | 14px / 600 / line-height 1.3 / `var(--text-h)` |
| `.install-callout__body` | 13px / 400 / line-height 1.5 / `var(--text)` |
| `.install-callout__dismiss` | Ghost button, right-aligned, minimum 44px touch target |

### Visual Treatment

```css
.install-callout {
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: 12px;
  padding: 10px 12px;
  border-radius: 8px;
  border: 1px dashed var(--accent-border);
  background: var(--accent-bg);
  margin: 0 16px 0;  /* inset from workspace edges */
  flex-shrink: 0;
}
```

Rationale: This is the exact pattern of `.diag-capture-cta` (Diagnostics panel capture prompt). Re-using that visual treatment gives the callout a familiar, non-alarming appearance consistent with the app's informational banners.

### Placement in DOM

The callout renders as a flex child directly inside `.workspace` (after `.board-header`, before `.workspace__body`). It is not portaled to `document.body`. No z-index needed.

### Visibility Rules (interaction states)

| State | Rendered | Notes |
|-------|----------|-------|
| Non-Chrome browser | No | `isChromeBrowser()` guard; INSTALL-06 |
| Chrome, `beforeinstallprompt` not yet fired | No | `isInstallable` from `usePWAInstall` hook |
| Chrome, installable, `shouldShowInstallCallout()` = false | No | Cooldown or permanent suppress |
| Chrome, installable, first workspace visit after story creation | Yes | Default visible state |
| User dismisses | Hidden immediately, cooldown written to localStorage |
| User has installed (sxr:pwa:installed = true) | Never shown | Permanent suppress |

### Dismiss Interaction

- Dismiss button: `×` character, `btn-ghost` class, minimum 44px touch target via `min-height: 44px`
- On click: hide callout immediately, call `recordInstallDismiss()`, set local state `showInstallCallout = false`
- No animation on dismiss — instant hide (consistent with other in-page elements in this app)
- No confirm dialog — dismissal is non-destructive

## Copywriting Contract

| Element | Copy |
|---------|------|
| Callout headline | "Add Story X-Ray to your desktop" |
| Callout body | "Click the install icon in your Chrome address bar to keep it a click away." |
| Dismiss button label | "×" (aria-label: "Dismiss install prompt") |
| Empty state | Not applicable — callout either shows or does not |
| Error state | Not applicable — no user input in install flow |
| Destructive confirmation | None — no destructive actions in this phase |

Copy rationale:
- Headline: imperative verb + product name + benefit destination — matches the direct CTA style of `COPY` in `EmailCaptureModal`
- Body: points to the Chrome URL bar install button (INSTALL-03 requirement) and names the benefit concisely (two-line max at 13px in a 360px container)
- No "Install now" button in the callout — the design does NOT call `deferredPrompt.prompt()` (see RESEARCH.md INSTALL-03 and Anti-Patterns section)
- No "No thanks" link needed (unlike EmailCaptureModal) since the × dismiss is sufficient for this lighter-weight UI

## Accessibility Requirements

| Requirement | Implementation |
|-------------|---------------|
| Dismiss button touch target | `min-height: 44px`, `min-width: 44px` on `.install-callout__dismiss` |
| Dismiss button accessible name | `aria-label="Dismiss install prompt"` |
| Callout role | `role="status"` on `.install-callout` — advisory, non-interrupting |
| Focus management | No focus trap; callout is inline, not modal |
| Keyboard dismiss | Dismiss button is a `<button>`, natively keyboard-accessible |
| Color contrast | Headline `var(--text-h)` on `var(--accent-bg)` — passes WCAG AA at both light/dark values |

## Implementation Notes for Executor

1. **Do not reuse `capture-overlay`** — the install callout is not a modal. No backdrop, no `position: fixed`, no z-index above 10.

2. **CSS placement** — Add `.install-callout` styles to `src/index.css` in a new `/* ── PWA Install Callout ── */` section, following the established section comment pattern.

3. **Callout position in JSX** — Place `{showInstallCallout && <PWAInstallCallout ... />}` as a direct child of `.workspace`, between `.board-header` and `.workspace__body`.

4. **Dark mode** — All tokens (`var(--accent-bg)`, `var(--accent-border)`, `var(--text)`, `var(--text-h)`) respond to `prefers-color-scheme: dark` automatically via `:root` overrides. No dark-mode-specific CSS needed in the callout.

5. **Mobile** — On viewports <= 768px, the callout remains inline (not fixed). `padding: 8px 10px` to match the compressed header padding on mobile (see `@media (max-width: 768px)` `.board-header` rule).

6. **No animation** — No enter/exit animation. The callout appears and disappears instantly. This matches all other conditional elements in the app.
